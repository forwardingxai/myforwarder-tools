## 1. 문제

- 견적 담당자는 견적을 낼 때마다 선사별 로컬차지를 각자의 엑셀에서 찾아 견적서 표에 옮긴다. 운영 담당자는 선사 청구서를 받을 때 같은 자료를 다시 찾아 대조한다.
- 개인 엑셀은 갱신 시점이 제각각이라, 정부 고시 인상분(보안료·항만안전관리비)이나 선사 THC 인상이 빠져 있기 쉽다.
- 선사마다 항목을 묶는 방식이 달라서 숫자만 나란히 놓으면 틀린다. 예를 들어 머스크는 부두사용료(W/FAG)를 THC에 포함하고, 몇몇 선사는 부산 W/FAG에 보안료를 더해 받는다.
- 위험물(DG)은 선사에 따라 일반 THC와 같기도 하고 훨씬 높기도 해서, 선사 선택이 곧 원가가 된다.
- 목표: 컨테이너 종류·규격·수량을 고르면 선사들의 로컬차지가 **같은 항목 체계로** 정리되어 나오고, 고른 선사의 견적서 표를 엑셀에 그대로 붙여넣는다. 핵심은 "조회"보다 **"정형화"**다.

## 2. 데이터 — 선사 공식 Tariff

### 2-1. 어디서 오나
- 컨테이너 정기선사 대부분이 자사 사이트에 국내 로컬차지(Local Charge, Tariff)를 공개한다. 조회 화면, PDF, 엑셀, 공지사항 등 모양은 제각각이다.
- 2026-10-20 기준으로 38개 선사 사이트를 로그인 없이 확인했다. 공개 25곳, 일부 공개 5곳, 미공개 8곳이었다. 여기에 ESL을 미공개 선사로 더해 39곳을 보여 준다.
- 저는 AI 브라우저 에이전트(aside)에게 선사 사이트를 돌며 표를 모으게 했고(6,161행), 그 결과를 Claude가 검증·정규화했어요.
- 공공 API(해양수산부 화물운임공표)도 있지만, 선사 공식 Tariff가 더 세분화되어 있어서 기준값으로는 선사 Tariff를 썼다. 공공 API는 교차 확인용으로 남겨 뒀다.

### 2-2. 직접 모을 때(길 B)
- 에이전트에게 선사 목록과 아래 열을 주고 "로그인 없이 볼 수 있는 곳만, 사이트에 적힌 금액 그대로, 추정하지 말 것"을 꼭 지시한다.
- 원천 행(1행 = 금액 1개): 선사 · 국적구분 · 수출입 · 항구(UN/LOCODE) · 적용 항로 · 표준 항목 · 사이트 표기 항목명 · 화물 종류(DRY/REEFER/DG/OOG) · 규격(20/40/40HC) · 단위(컨테이너당/B/L당) · 통화 · 금액 · 발효일 · 만료일 · 비고 · 출처 URL
- 선사 사이트 이용약관을 지키고, 로그인이 필요한 화면이나 자동 조회를 막아 둔 곳은 모으지 않는다. 요청 사이에 충분히 쉰다.
- 선사 PDF·엑셀 파일명은 개정 때마다 바뀌니 파일 주소 대신 **메뉴 경로**를 기록해 두면 다음 달 갱신이 쉽다.
- 원천 파일은 `raw/날짜/` 폴더에 두고 저장소에 올리지 않는다. 화면에는 정리한 요약값만 쓴다.

### 2-3. 원천 → 화면 데이터 필터
1. 로컬차지만(해상 할증료 BAF·LSS 등은 제외), 지금 유효한 요율만(만료일 없음), 원화(KRW)만
2. 수출(또는 수출입 공통), 부산 항구(KRPUS·KRPNC·KRBNP) 또는 전국 공통
3. LCL 전용 요율, 추가 씰(Extra Seal)은 제외
4. 40'HC는 40'으로 합친다

2026-10-20 기준 결과: 선사 39곳 × 항목 18개 = 702칸. 확인 373 · 미확인 229(최빈값 추정 159, 범위 추정 70) · 해당 없음 38 · 일반 서류비 적용 34 · 확인(오래된 공지) 16 · W/FAG에 포함(추정) 10 · THC에 포함 2.

## 4. 규칙

### 4-1. 대표값 고르기 (한 선사에 같은 항목이 여러 줄일 때)
1. 부산 정확 일치 > 전국 공통
2. 전 항로·한중·한일·아시아 항로 > 원양 특정 항로
3. (DG) IMO 3~9급 > IMO 1·2·7급
4. 최신 발효일
- 값이 여러 개면 최저~최고 범위를 함께 저장해 마우스를 올리면 보여 준다.
- **DG 판정:** DG 줄 중 리퍼·오픈탑·플랫랙·탱크 기반 위험물은 빼고 **드라이 컨테이너 위험물만** DG로 본다. 화면에 "DG 기준: 드라이 컨테이너 위험물, 한중·아시아 항로, IMO 3~9급"을 늘 적는다.

### 4-2. 상태
| 상태 | 합계 | 화면 |
|---|---|---|
| 확인 | 금액 | 숫자 |
| 확인(오래된 공지) | 금액 | 숫자 + 연도 태그 |
| THC에 포함 | 0 | "THC 포함" |
| W/FAG에 포함(추정) | 0 | "W/FAG 포함" |
| 일반 서류비 적용 / 해당 없음 | 0 | — |
| 미확인 → 추정(최빈값) | 최빈값 | 회색 숫자 + "추정" |
| 미확인 → 추정(범위) | 최저~최고 | 회색 범위 + "추정" |
| 미확인(추정 불가) | 0 | "미확인" |

### 4-3. 추정 규칙 (선사 값이 없을 때)
1. 같은 **국적구분(국적 / 외국적)** 의 확인 선사 값을 근거로 한다. 그룹 안 확인 선사가 5곳 미만이면 전체 선사로 넓힌다.
2. 가장 많은 값(최빈값)이 근거 선사의 50% 이상이면 그 값을 쓴다.
3. 50% 미만이면 최빈값 대신 범위(최저~최고)로 보여 준다.
4. 근거 선사가 5곳 미만이면 추정하지 않는다.
5. 위험물 서류비·DG 할증처럼 선사마다 다른 항목은 추정하지 않는다.
6. 추정값은 반드시 "추정"으로 표시하고, 근거를 문장으로 보여 준다. 예: "확인된 외국적 선사 7곳 중 6곳이 290원을 청구합니다."

국적과 외국적을 나누는 이유: 40' DG THC는 국적선사 대부분이 일반 THC와 같은 210,000원인데, 외국적선사는 190,000~385,000원으로 흩어져 있다. 전체 최빈값을 쓰면 외국적 미공개 선사가 싸게 잡힌다.

### 4-4. 이중 계산 막기
- 부산 W/FAG가 4,574원/9,148원인 선사(= 4,429원/8,858원 + 보안료 145원/290원)는 PFS를 "W/FAG에 포함"으로 보고 추정값을 채우지 않는다.
- 머스크는 W/FAG가 THC에 포함되어 있어 W/FAG를 추정하지 않는다.

### 4-5. 합계·정렬
- 합계 = (컨테이너당 항목 합 × 수량) + (DOCS FEE × B/L 수). 범위 추정이 있으면 "최저~최고"와 "추정 포함"
- 합계 낮은 순(범위면 최저값 기준). 확인값이 하나도 없는 선사는 구분선 "공식 Tariff 미공개 선사 (추정값)" 아래에 따로 묶는다.

## 5. 화면·복사 규칙

- 입력 바: 컨테이너 종류 · 규격 · 수량 · B/L 수 · 선사 범위 · 선사 검색. 바꾸면 바로 다시 계산(조회 버튼 없음)
- 비교표: 선사명 열과 합계 열은 가로로 밀어도 고정. 선사명은 공식 Tariff 페이지 새 창 링크
- 선사 이름 옆 세모(▸)나 행을 누르면 그 아래에 견적서용 표(항목 | 단위 | 단가 | 수량 | 금액 | 비고)가 펼쳐진다. 0원·포함 항목은 행에서 빼고 비고에 포함 관계를 적는다.
- [견적서 표 복사]는 탭 구분, 금액은 쉼표 없는 숫자. 범위 추정 항목은 "최저~최고" 글자로 넣는다(숫자를 지어내지 않는다).
- 비교표 전체도 [표 복사]·[엑셀(CSV) 내려받기]로 가져간다. 선사를 체크하면 그 선사만, 체크가 없으면 화면에 보이는 선사 전체.
- 표 아래 고정 문구: "기준일 … · 선사 공식 Tariff 기준 · 부가세 별도 여부와 실제 청구액은 선사 확인 필요"

## 6. 단계별 프롬프트

한 번에 다 시키면 AI도 놓치는 게 생겨요. 아래처럼 나눠서 시키고, 단계마다 결과를 눈으로 확인하세요. 제가 실제로 이 순서로 만들었어요.

**01 맥락 읽기**
```
너는 포워딩 영업·운영 실무자를 돕는 웹 도구 개발자야. 이 폴더의 kit 파일(국내 부대비용 조회기)을 처음부터 끝까지 읽고, 무엇을 만들지 5줄로 요약한 뒤 작업 계획을 단계별로 보여 줘. 단계마다 멈추고 나에게 확인받아. 키트에 없는 판단이 필요하면 멈추고 물어봐. 나는 코딩 초보자라 명령어는 한 줄씩 설명해 줘.
```

**02 데이터 배치**
```
data/ 폴더에 내려받은 local-charge-busan-export.json을 두고, 선사 수·항목 수·상태별 칸 수를 집계해서 kit 2-3절 숫자와 같은지 표로 보여 줘. (직접 모은 원천이 있다면 kit 2-3·4-1·4-3절대로 정리 스크립트를 먼저 만들어 줘. 원천 폴더 raw/는 .gitignore에 넣어.)
```

**03 공통 구조 변경** — 도구를 여러 개 모은 사이트일 때만
```
도구 목록 파일에서 영역(area)을 하나짜리 글자에서 목록으로 바꿔 줘. 이 도구는 ["sales","ops"]로 영업·운영 두 필터에 함께 나오게 하고, 색은 첫 번째 영역을 따르게 해. 이미 있는 도구가 전과 똑같이 보이는지 확인할 주소를 알려 줘.
```

**04 화면 골격**
```
tools/local-charge.html 한 파일로 화면 골격을 만들어 줘. 위에서부터 ① 입력 바 ② 선사 비교표 ③ 견적서용 표 자리 ④ 데이터 안내(출처·기준일·선사 수·상태 읽는 법·면책). 이 단계에서는 계산 없이 JSON을 읽어 선사와 항목이 표에 나오기까지만. 확인값이 하나도 없는 선사는 구분선 아래에. 375px에서 선사명 열 고정 + 가로 스크롤.
```

**05 계산 로직**
```
kit 4절의 상태·추정·이중 계산 막기·DG 대체 규칙과 합계 공식을 넣어 줘. 추정 칸은 회색 글자 + "추정" 태그, 마우스를 올리면 근거 문장. 입력을 바꾸면 바로 다시 계산하고 합계 낮은 순으로. 다 되면 kit 7절 1~6번을 화면에서 계산해 기대값과 표로 비교해 줘.
```

**06 견적서 표 복사**
```
선사 행(또는 이름 옆 세모)을 누르면 그 아래에 견적서용 표가 펼쳐지게 해 줘. kit 5절 규칙대로 0원·포함 항목은 빼고 비고에 포함 관계를 적고, [견적서 표 복사] 버튼 하나만 눈에 띄는 색으로. 탭 구분·쉼표 없는 숫자로 복사하고 2초간 "복사됨".
```

**07 검증**
```
kit 7절 확인 목록을 브라우저에서 직접 해 보고, 기대값과 화면 결과를 표로 보여 줘. 하나라도 다르면 원인을 찾아 고친 뒤 다시 보여 줘. 엑셀 붙여넣기는 내가 직접 해 볼 수 있게 방법을 알려 줘.
```

## 8. 내 업무에 맞게 바꿔 보기

다 만들었다면 이제부터가 진짜 재미있어요. 프롬프트 몇 줄만 바꾸면 내 업무에 딱 맞는 도구가 돼요.

- **회사 견적서 양식:** 견적서 표의 열 순서·항목명(국문/영문)을 회사 양식에 맞추고, 해상운임·핸들링 칸을 더해 견적서 한 장으로
- **청구서 대조(운영):** 선사 청구서 금액을 붙여넣으면 조회 값과 비교해 차이 나는 항목만 표시
- **구글 시트:** 선사·컨테이너·수량을 넣으면 로컬차지 합계가 나오는 Apps Script
