# 문체 가이드 — 마이포워더 도구

> 2026-10-17 · 화면 문구, tools.json, 키트, 랜딩에 모두 적용한다. 새 도구를 만들 때 이 파일을 함께 읽는다.

## 1. 누가 읽나, 무엇을 남기나

- 읽는 사람: 포워딩·SCM 실무자, 강의 수강생, AI로 일을 줄여 보고 싶은 사람
- 남기고 싶은 감정: "AI로 이게 된다고?" → "나도 해 볼 수 있겠는데?" → "이 사람한테 더 배우고 싶다"
- 그래서 문구는 ① 바로 쓸 수 있게 돕고 ② 만든 과정을 솔직하게 보여 주고 ③ 만든 사람이 보이게 쓴다.

## 2. 말투

| 원칙 | 이렇게 | 이렇게 말고 |
|---|---|---|
| 해요체로 통일 | 바로 복사돼요 | 복사됩니다 / 복사 가능 |
| 옆자리 실무 선배처럼 | 이름 몇 글자만 입력하세요 | 검색어를 입력하시기 바랍니다 |
| 만든 사람의 1인칭 | 제가 거친 순서를 담았어요 | 개발 과정이 제공됩니다 |
| 결과부터 | 보낼 문구까지 한 번에 복사돼요 | 복사 기능을 지원합니다 |
| 짧게, 한 문장에 한 가지 | 엑셀에서 바로 열려요. | 엑셀에서도 활용 가능하며 다양한 용도로 사용할 수 있습니다 |
| 실무 장면으로 | 관세사가 "장치장 코드가 뭐예요?" 하고 물으면 | 장치장 코드 조회가 필요한 경우 |

## 3. 피할 표현 (번역투·공문체)

| 피할 표현 | 바꿀 표현 |
|---|---|
| ~을 통해 | ~로 |
| ~에 대해 | ~를 / ~ 이야기 |
| ~할 수 있습니다 (반복) | ~해요 / ~하면 돼요 |
| 제공합니다 / 지원합니다 | 드려요 / 돼요 / 담았어요 |
| 해당 ~ | 이 ~ / 그 ~ |
| ~되어지다 | ~되다 |
| 진행하다 (남발) | 하다 |
| 다양한 / 효율적인 / 혁신적인 | 구체적인 숫자나 장면 |

## 4. 용어

| 쓰는 말 | 안 쓰는 말 | 비고 |
|---|---|---|
| 장치장 코드 | 보세구역 부호 | 화면에서는 실무 용어. 키트·데이터 설명에서는 "부호(코드)" 가능 |
| 관세사 | 관세사님 | 화면 문구에서는 존칭 없이 |
| 구분(추정) | 유형, 카테고리 | 추정값에는 반드시 "추정" |
| 즐겨찾기 · 최근 조회 · 내 메모 | 북마크 · 히스토리 | |
| 알려 주기 · 제보 | 피드백 제출 | |

## 5. 퍼널 문구 초안 (site.json에 넣을 것)

`site.json`의 칸이 채워져야 화면에 나온다. 사실과 다른 내용(경력 연수, 수강생 수 등)은 넣지 않는다. `{ }`는 직접 채울 자리.

**만든 사람 (creator)**
- name: `{이름 또는 활동명}`
- role: `포워딩 × AI 강의 · 마이포워더 도구 제작`
- bio: `포워딩 현장에서 {맡았던 일}을 했어요. 지금은 실무자가 AI로 직접 일을 줄이는 방법을 가르치고, 그 과정에서 만든 도구를 여기에 하나씩 공개해요.`
- links: 강의 페이지, 블로그·유튜브, 링크드인 등

**다음 걸음 (cta)** — 셋 중 하나를 고른다

| 목적 | title | body | primary | secondary |
|---|---|---|---|---|
| 강의로 연결 | 포워딩 실무에 AI를 붙이는 법, 처음부터 같이 해 봐요 | 이런 도구를 처음부터 끝까지 AI로 만드는 과정을 한 단계씩 보여 드려요. 코딩을 몰라도 괜찮아요. | 포워딩 × AI 강의 보기 | 새 도구 소식 받기 |
| 소식 구독 | 하루 하나씩, 실무 도구가 늘어나고 있어요 | 새 도구가 나오면 만든 과정과 키트를 함께 보내 드려요. | 새 도구 소식 받기 | 지금까지 만든 도구 보기 |
| 업무 제안 | 다음 도구는 당신의 업무일 수도 있어요 | 매일 반복하는 일이 있다면 알려 주세요. 도구로 만들어 공개하고, 만드는 과정도 함께 나눌게요. | 업무 제안하기 | 강의 둘러보기 |

**연락 (contact)**: label `제안·제보 보내기`, href는 이메일(`mailto:`)·카카오톡 채널·구글폼 중 하나
