# 공유 이미지 가이드 — 마이포워더 도구

> 2026-10-19 확정(D01 장치장 코드 조회기 C″안). 모든 도구의 카카오톡·링크드인 공유 이미지를 이 스타일로 만든다.
> 틀: `scripts/share-image.html` · 만들기: `npm run share-image -- {slug}` → `thumbs/{slug}-og.png`(공유 이미지) + `thumbs/{slug}.png`(랜딩 카드 썸네일)

## 1. 왜 이 스타일인가

- 피드와 대화방에서 **검정 바탕**이 가장 먼저 눈에 띈다.
- 오른쪽의 **실무 질문 → 바로 나온 답** 장면이 "이거 내 얘기네"를 만든다. 무엇을 하는 도구인지 설명보다 장면으로 보여 준다.
- 왼쪽은 **도구 이름과 한 줄 설명**만. 작은 미리보기에서도 이름이 읽힌다.
- 모든 도구가 같은 배치라 "마이포워더 도구"라는 하나의 브랜드로 쌓인다.

## 2. 고정 (도구마다 바꾸지 않는 것)

| 요소 | 규칙 |
|---|---|
| 크기 | 1200×630 |
| 바탕 | `--bg-dark` 검정 한 색. 그라데이션·사진·패턴 없음 |
| 배치 | 왼쪽(태그 → 제목 2줄 → 한 줄 설명 2줄, 아래 브랜드·주소) / 오른쪽(누가 묻는지 → 질문 말풍선 → 답 카드) |
| 글꼴 | Pretendard, 굵기 400·500. 답의 값만 모노 글꼴 |
| 브랜드 | 흰 원 안 M 로고 + "마이포워더 도구" + `myforwarder-tools.vercel.app` |
| 말풍선·카드 | 말풍선은 반투명 흰 면(왼쪽 아래 모서리만 좁게), 답 카드는 짙은 회색(오른쪽 아래 모서리만 좁게) |

## 3. 영역에 따라 바뀌는 것 (색)

`tools.json`의 `area`가 정한다. 직접 색을 고르지 않는다.

| 영역 | 태그 바탕 | 답의 값 |
|---|---|---|
| 운영 `ops` | 코발트 `--accent-ops` | 코발트 |
| 영업 `sales` | 라임 `--accent-sales`(글자는 짙은 녹색) | 라임 |

색은 이 두 곳(태그·답의 값)에만 쓴다. 디자인 규칙의 "영역 태그"와 "다크 블록 위 큰 숫자"에 해당한다.

## 4. 도구마다 쓰는 것 — `tools.json`의 `share`

```json
"share": {
  "title": ["장치장 코드", "조회기"],
  "sub": ["이름 몇 글자, 초성, 약칭으로", "전국 장치장 코드를 바로 찾아요"],
  "who": "관세사",
  "question": "\"장치장 코드가 뭐예요?\"",
  "answer": "03077011",
  "answerNote": "에이치엠엠피에스에이신항만(주) · 부산세관"
}
```

| 칸 | 쓰는 법 |
|---|---|
| `title` | 도구 이름을 2줄로 나눠 배열로. 한 줄은 7자 안팎 |
| `sub` | 한 줄 설명을 2줄로. 한 줄 16자 안팎, 해요체 |
| `who` | 그 질문을 실제로 하는 사람(관세사, 화주, 팀장, 해외 파트너 등) |
| `question` | 실무에서 실제로 듣는 한마디. **한 줄(약 16자)** — 넘으면 스크립트가 경고 |
| `answer` | 도구가 내놓는 결과 하나. 코드·금액·날짜처럼 짧고 큰 값(10자 안팎). 글자 답이면 `"answerStyle": "text"` |
| `answerNote` | 답을 설명하는 한 줄(이름·조건·출처) |
| `tag` | 비우면 "운영 · 무료 도구"처럼 자동. 바꿀 때만 적는다 |

## 5. 내용 규칙

- **답은 실제 데이터에서 고른다.** 지어낸 값을 실제처럼 쓰지 않는다. 예시·가상 값이면 `answerNote`에 "(예시)"를 붙인다.
- 개인정보·사내 정보(실제 고객사명, 실제 견적가)는 넣지 않는다.
- 문구는 docs/voice-guide.md의 말투를 따른다.

## 6. 만드는 순서

1. `tools.json`에 `share` 칸을 쓴다.
2. `npm run share-image -- {slug}` (처음 한 번은 `npm install`). 경고가 나오면 문구를 줄이고 다시 실행한다.
3. `thumbs/{slug}-og.png`를 열어 확인한다. 카카오톡 크기(가로 300px)로 줄여도 제목과 답이 읽히는지 본다.
4. 도구 HTML의 `<head>`에 공유 정보를 넣는다(D01 `tools/bonded-area-code.html` 참고): `og:title`, `og:description`, `og:url`, `og:image`(= `https://myforwarder-tools.vercel.app/thumbs/{slug}-og.png`), `og:image:width` 1200, `og:image:height` 630, `twitter:card` summary_large_image.

## 6-1. 랜딩(사이트) 공유 이미지

`site.json`의 `share` 칸(같은 항목 + `area`)을 쓰고 `npm run share-image -- site` → `thumbs/site-og.png`. 사이트 이미지는 라임(`area: "sales"`)으로 도구 이미지와 구분한다. 도구 개수·날짜처럼 시간이 지나면 틀리는 값은 넣지 않는다.

## 7. 랜딩 카드 썸네일 (2026-10-20 같은 스타일로 통일)

같은 명령이 랜딩 카드 썸네일 `thumbs/{slug}.png`(1280×800, 16:10)도 함께 만든다. 같은 `share` 문구를 쓴다.

- 랜딩 카드에서는 가로 약 340px로 줄어 보이므로 **오른쪽 대화 장면(누가 묻는지 → 질문 → 답)만 크게** 담는다.
- 도구 이름·설명은 카드 아래에 이미 나오므로 썸네일에서는 뺀다.
- 바탕·말풍선·답 카드·색 규칙은 공유 이미지와 같다. 랜딩·공유 미리보기·도구 화면이 한 결로 이어진다.
