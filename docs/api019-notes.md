# API019 통계부호 — 세관부호 목록용 메모

> 2026-10-16 정리 · 근거: UNI-PASS OpenAPI 연계가이드 v4.1 3.2.19절(원본 PDF는 `docs/reference/`, 커밋 제외)
> 용도: API005 전국 수집에 쓸 관할세관코드 목록 + `customsName`(세관명) 보강

## 1. 요약

| 질문 | 답 |
|---|---|
| 무엇을 주나 | 관세청이 쓰는 각종 부호표(내국세율, 국가코드, 통화코드, 세관부호 등). 부호 종류를 골라서 받는다 |
| 세관부호는 | 부호 종류 **`A09`(세관부호)** |
| 목록형인가 | 목록형. A09는 종류만 넣으면 해당 부호 전체가 온다(코드명·코드값 추가 입력이 필요한 종류는 A08·A10·A11뿐) |
| 호출 수 | 세관부호 전체 = **1회** |
| 응답 형식 | XML만, UTF-8 |
| 인증키 | `.env`의 `UNIPASS_API019_KEY` (API005와 키가 다름) |

## 2. 요청

- 주소: `https://unipass.customs.go.kr:38010/ext/rest/statsSgnQry/retrieveStatsSgnBrkd`
- 파라미터

| 이름 | 뜻 | 필수 | 우리 값 |
|---|---|---|---|
| `crkyCn` | 인증키 | 필수 | `UNIPASS_API019_KEY` |
| `statsSgnTp` | 부호 종류 | 필수 | `A09` |
| `cdValtValNm` | 코드명 | A08·A10·A11만 필수 | 안 넣음 |
| `cdValtVal` | 코드값 | A08·A10·A11만 필수 | 안 넣음 |

- 키가 주소에 들어가므로 요청 주소는 출력·저장하지 않는다.

## 3. 응답

**A09는 가이드 표와 다른 구조로 온다(2026-10-16 시험 호출 1회로 확인).** 반복 태그가 `statsSgnQryVo2`이고 항목 이름도 다르다. 파서는 두 구조를 모두 받도록 만든다.

| A09 실제 항목 | 뜻 | 우리 필드 | (가이드 표의 항목) |
|---|---|---|---|
| `cdValtVal` | 세관부호 3자리 | `code` | `statsSgn` |
| `cdValtValNm` | 세관명 | `name` | `koreBrkd` |
| `englAbrtNm` | 영문 약어(대부분 빈칸) | 안 씀 | `englAbrt` |
| `valtValEnglRmrkCn` | 영문 이름 | 안 씀 | — |

- 건수는 `tCnt`. 오류면 `tCnt -1` + `ntceInfo`에 사유.

## 3-1. 시험 호출 결과 (2026-10-16, 1회)

- 60건 · XML 10.4KB · 0.3초 → `data/customs-codes.json`(code·name)
- `000`~`009` 10건은 관세청 본청·부서·소속기관(관세평가분류원 등) — 세관 아님
- `010`~`154` 50건은 세관 36곳(마산수출자유지역 `059` 포함) + 지원센터 14곳
- 본관세관·지세관 구분 항목은 응답에 없다
- 이름이 같은 부호가 있다: 용당세관 `035`·`039`

## 4. 참고

- 같은 API의 `A08`(보세구역 부호)은 코드명이나 코드값을 넣어야 해서 전체 목록용이 아니다. 장치장 목록은 API005로 받는다.
- 부호 종류 전체 목록은 My Customs의 통계부호 조회 화면에서 볼 수 있다고 가이드에 적혀 있다.
