### 1-3. 갱신 방법

- 갱신 트리거: ① 매년 다음 해 적용 고시(매년 10-31까지 공표) ② 연중 일부개정·정정 고시 ③ 유가 연동 변경(별표1 34조, 분기 단위)
- 절차: 새 고시 원본을 `raw/safe-rate/{고시번호}/`에 저장 → `scripts/build-safe-rate.mjs` 실행 → 검증 케이스(8장) 전체 통과 → `data/safe-rate/{버전}/` 생성 → `meta.json`에 적용기간 추가 → push
- 버전 공존: 고시 버전별 폴더 유지. `meta.json`의 적용기간은 배열로 두어 분기 단위 구간도 표현. 화면은 오늘 날짜가 속한 버전을 기본 선택하고, 적용기간 경계 전후 30일은 "이전 고시 / 현재 고시" 전환 토글 노출
- 커밋 원칙: `raw/`(원본 xlsx·hwpx·pdf)는 커밋하지 않음. 가공 JSON과 `meta.json`(출처·고시번호·시행일·건수)만 커밋

## 2. 문제 정의와 사용자

### 2-1. 실무 상황

> 화주: "경기도 용인에서 컨테이너 작업해서 수출 보내려면 운송료 얼마예요?"
> 포워더: POL이 부산이면 ① 부산 왕복 운임, ② 공컨을 부곡(의왕ICD)에서 픽업하는 편도 운임을 각각 20FT·40FT로, 20톤 초과 화물은 톤수별 금액까지 안내해야 함.

기존 방식의 문제는 세 가지입니다. 기점·행선지를 매번 고르고 조건별로 따로 계산해야 하고, 운송사는 할증을 요율로 알려주지만 화주는 "그래서 얼마인지"를 묻고, 행선지를 동 단위로 모르는 경우가 많습니다.

### 2-2. 사용자

| 사용자 | 목적 |
|---|---|
| 포워더 영업 | 신규·견적 단계 화주 문의에 즉시 20/40FT·톤수별 금액 안내, 견적 문구 복사 |
| 포워더 운영 | 진행 중인 선적 건의 고객 운송료 문의 안내(중량·할증·운송형태 변경 시 재계산), 운송사 청구서의 할증·운송형태 적용 내역 확인 |
| 화주 물류 담당 | 받은 운송 견적의 산출 근거 확인 |

### 2-3. 핵심 가치

"주소 하나 넣으면, 화주가 낼 운송료를 운송 방식별·톤수별 금액으로 바로 보여준다."

## 3. 범위

### 3-1. 1기 포함

- 기점 14곳 왕복 운임, 부산신항·부산북항·광양항 ↔ 의왕ICD 편도 운임
- 수출/수입 흐름 선택(수출 = 공컨 수령 장소, 수입 = 공컨 반납 장소)
- 20FT·40FT 동시 표시, 45FT(40FT × 112.5%, 안전위탁·안전운송운임만)
- 운임 종류 3종: 화주 운임(안전운송운임, 기본) / 안전위탁운임 / 운수사업자 간 운임
- 중량할증 금액표(고시 기준만, A안) + PTA 예외
- 할증 전 항목(별표1 23조) + 다수 할증 합산 규칙(22조)
- 운송형태(고급 조건, 접힘): 복화, COMBINE 가·나목, 밥테일, 온그라운드(운행 횟수 선택), 포지셔닝, 셔틀, 철도CY 직송
- 수입 흐름의 인천터미널 공컨 반납 +40,000원(9조 가목 단서)
- 고시 외 비용 입력: 상차비(CY 작업비) — 고시 금액과 분리 표시
- 부가세 포함 토글
- 주소 검색(지번·도로명) + 시군구만 선택 시 범위 표시 + 읍면동 직접 선택
- "다른 항구로 보내면?" — 같은 행선지의 14개 기점 운임 정렬 비교
- 견적 문구 복사
- 조건부 안내: 27조 실비, 24조 나목 화주 문전 대기료, 23조 파목 5) 위험물 재운송, 31조 과적 회차

### 3-2. 1기 제외 → 2기 후보

- 거리(km) 직접 입력(고시 미기재 구간, 6조 다목), 공차 운행(14조, 공차 거리 입력 필요)
- COMBINE 다·라목(상·하행 규격이 다른 경우)
- 부산신항·광양항 배후단지 편도 운임표, 대기료·배차 취소료 계산기
- 이전 고시와 운임 비교·추이 차트
- 시멘트 품목, 전배운송 운임
- 운송사 자체 할증 기준 입력(B안), 포워더 마진 입력

| # | 규칙 | 근거 |
|---|---|---|
| R1 | 기본 운임 = 운임표[기점][시도+시군구+행정동][규격][운임종류] | 1호 가목 2), 별첨 |
| R2 | 모든 운임은 왕복이 원칙. 편도는 행선지가 편도표에 있고(= 서울·인천·경기·강원 춘천·홍천) 공컨 반납·수령지가 의왕ICD일 때 적용. 지역 판정은 "편도표에 키 존재"로 함 | 9조 가목 |
| R3 | 수입 흐름 + 공컨 반납지 인천터미널 → 의왕ICD 편도운임 + 40,000원(정액, 할증 미적용). 수출 흐름(공컨 수령)의 인천터미널은 고시 미규정 → 금액 없이 "고시 미규정 — 운송사 협의" 표시, 견적 문구에서 제외 | 9조 가목 단서 |
| R4 | 냉동·냉장, O/T, FR, 탱크, 플렉시백, 덤프 컨테이너는 편도 조건이어도 왕복 → 편도 카드 비활성 + 사유 표시. 위험물 선택 시 편도 금액은 표시하되 "9조 나목상 왕복 적용 가능성 — 운송사 확인" 경고 | 9조 나목 |
| R5 | 45FT = 40FT 운임 × 112.5%(안전위탁·안전운송운임만). 운수사업자 간 운임은 고시 미규정으로 미표시 | 19조 |
| R6 | 중량할증: 20FT 내품 20톤 초과, 40FT 23톤 초과부터 매 1톤 10%. 구간 "n톤 초과 ~ n+1톤 이하". PTA는 20FT 21톤 초과부터 | 23조 가목 |
| R7 | 다수 할증: 가장 높은 할증률 100% + 나머지 각 50%, 3개 초과 시 높은 순 3개까지. 중량할증(누적 n×10%)은 1개 항목으로 취급 | 22조 |
| R8 | 할증은 금액이 아닌 요율을 먼저 합산한 뒤 금액으로 환산하고 1회 반올림 | 22조, 7조 |
| R9 | 모든 운임·요금은 십 원 단위에서 반올림(=100원 단위). 고시 금액은 모두 부가세 제외 기준 | 7조 |
| R10 | 부가세 포함 금액 = 합계 × 1.1(고시 금액은 100원 단위라 항상 정수, 원 단위 반올림은 고시 외 비용 입력 시에만 작동) | 8조 |
| R11 | 인천·평택 기점 할증은 운임표에 이미 반영 → 별도 할증 적용 금지 | 23조 카·타목 |
| R12 | 운송형태 배수: 복화 ×2(10조) / COMBINE 가목 20FT 2개 합계 200%, 나목 요건 4가지(동일화주·비할증·합계 20톤 미만·동일 상하차지) 충족 시 2개 합계 180%(11조, 배후단지·환적 제외) / 밥테일 1회 ×1·2회 ×2(12조) / 온그라운드 운행 1회 ×1·2회 ×2(13조 가·나·다목 각 100%) / 포지셔닝 ×0.5(15조) / 셔틀 편도 ×0.5·왕복 ×1(16조) / 철도CY 직송 ×0.5(17조) | 10~17조 |
| R13 | 상차비 등 고시 외 비용은 고시에 요율 없음(13조·28조는 차주 청구 금지 규정). 사용자 입력 금액을 별도 줄로 더하고 "고시 외 비용"으로 표기 | 13조, 28조 |
| R14 | 금액 계산 순서: ① A = 반올림(기본 운임 × 운송형태 배수 [× 1.125, 45FT]) ② S = 반올림(A × 합산 할증률) ③ 고시 운임 = A + S ④ + 정액(인천 반납 40,000원) ⑤ + 고시 외 비용 ⑥ 부가세 토글. 복화는 구간별로 할증 적용 여부를 지정: 고시 운임 = 기본 × 2 + Σ(구간별 반올림(기본 × 해당 구간 합산 할증률)) | 7·10·22조 (Fable 제안) |
| R15 | 편도 조건은 성립하나 해당 기점에 편도표가 없는 경우(울산·평택·인천 등) → "편도 운임표 없음 — 협의(6조 다목)" 표시 | 6조 다목 |

### 4-1. 조건부 안내 문구

| 조건 | 안내 | 근거 |
|---|---|---|

### 5-2. 주소 → 행정동 변환

1. 다음(카카오) 우편번호 서비스로 지번·도로명 검색(인증키 불필요)
2. 결과의 법정동 코드(`bcode`)로 `dong-map.json` 조회
3. 1:1이면 바로 결과, 1:N이면 후보 행정동을 모두 보여주고 금액 범위 표시
4. 매핑 실패 시 시군구까지만 확정하고 범위 표시 + 읍면동 직접 선택 유도
5. 빌드 시 고시 행정동명과 행정안전부 행정동명 매칭률 리포트 출력, 불일치는 `alias` 표로 수동 보정

## 7. 표기 원칙

- 기본 운임 라벨은 "화주 운임(안전운송운임)"

## 11. 도구 페이지 구성 (실행 영역 아래)

- 기능: 주소 한 번으로 운송 방식별·톤수별 금액, 14개 항구 비교, 견적 문구 복사
- 만든 과정: 벤치마킹 2곳 분석 → 고시 개정본 발견 → 원천 데이터 검증(거리→운임 함수관계, 인천·평택 위탁운임 배수 발견) → 상차비 사실 확인 → 다른 모델(Fable) 교차 검증으로 해석 오류 3건 수정 → UX 설계
- 프롬프트 구조(단계 제목만 공개): ① 벤치마킹 분석 ② 원천 고시 확정 ③ 데이터 정합성 검증 ④ 계산 규칙 조문화 ⑤ 교차 검증 ⑥ 화면 설계 ⑦ 검증 케이스 작성
- 관련 도구: D01 장치장 코드 조회기, D02 국내 부대비용 조회기(예정)
