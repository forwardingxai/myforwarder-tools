## 1. 문제

- 사용자: 포워딩 수출입 OP 담당자, SCM 담당자
- 반복 작업: 관세사가 수출·수입 신고를 위해 "장치장 코드가 어떻게 되나요?"라고 물으면, 담당자는 개인적으로 저장해 둔 메모(암묵지)를 뒤지거나 선사·입고지 창고에 다시 확인해 장치장명과 숫자 코드를 메일·메신저로 전달한다.
- 현재 문제: 코드를 모르는 경우 확인·회신에 시간이 걸리고, 담당자마다 아는 범위가 달라 업무가 사람에 묶인다.
- 끝난 뒤의 모습: 장치장명 일부만 입력하면 공식 코드가 나오고, 관세사에게 보낼 문구가 한 번에 복사된다.

## 2. 입력·출력

| 입력 | 형식 | 필수 | 예시값 |
|---|---|---|---|
| 1. 검색어 | 텍스트 (장치장명·코드·초성) | 필수 | `부산신항`, `ㅂㅅㅅㅎ`, 코드 일부 숫자 |
| 2. 지역 필터 | pill 다중 선택 | 선택 | 부산 · 인천 · 광양 · 평택 · 울산 · 공항 · 기타 |
| 3. 구분 필터 | pill 다중 선택 | 선택 | CY · CFS · 보세창고 · 공항화물 · 기타 |

- 세관 필터는 고급 필터(접힘)로 둔다 — 입력 3개 원칙 유지.
- 출력 1개: 일치 장치장 목록 (리스트형 / 카드형 전환)
- 출력 후 행동: **관세사 전달용 문구 복사** → 메일·메신저에 붙여넣기

## 3. 데이터·도메인 규칙

### 3-1. 데이터
- 출처 (2026-10-16 확정): 관세청 UNI-PASS OPEN API **API005 장치장정보조회** (2026-10-16 사용 승인)
  - 인증키: `.env`의 `UNIPASS_API005_KEY`에만 저장. 커밋·출력·로그 금지
  - 수집: `scripts/fetch-bonded-areas.mjs` → 원본 응답 `raw/`(커밋 제외), 정제본 `data/bonded-area-code.json`만 커밋
  - 호출 방식(2026-10-16 시험 호출 2회로 확인): 조건 없는 전체 조회는 불가(`tCnt -1`, "관할세관코드 또는 보세구역부호는 필수입력"). **전국 수집 = 관할세관코드(`jrsdCstmCd`)마다 1회씩, 관할세관 수만큼 호출.** 부산세관(030) 1회 = 366건 · XML 116.6KB · 0.8초. 호출할 관할세관코드는 `data/customs-codes.json`(API019 A09, 60건) 중 `010`~`154` **50곳**(세관 36 + 지원센터 14, 관세청 본청·부서·소속기관 `000`~`009` 10건 제외) → **전국 수집 = 50회**. 본관세관·지세관 구분 항목은 API019 응답에 없음
  - 일일 호출 한도: 확인 못함. 수집 스크립트는 호출 사이 1초 간격, 오류 응답(`tCnt -1`)이나 한도 응답이 오면 즉시 멈추고 보고
  - 세관명: API019 통계부호(A09)로 확보(2026-10-16 승인·수집, 당초 D01 배포 후 예정에서 앞당김) → `data/customs-codes.json`. 스크립트는 이 파일이 있을 때만 세관명을 채우고, 목록에 없는 부호는 비워 둔다(추정으로 채우지 않음)
  - 명세 요약: `docs/api005-notes.md`, `docs/api019-notes.md`
  - (검토했던 대안: UNI-PASS 보세구역 조회 화면 엑셀 내려받기, 공공데이터포털 파일데이터)
- 범위: **1차부터 전국 전체.** 화면에서는 주요 항만(부산·인천·광양·평택·울산)·공항 화물터미널·CFS를 필터와 바로가기로 앞세운다.
- 예상 규모: 수천 건 · JSON 수백 KB (전송 압축 후 더 작음) → 클라이언트 검색으로 충분, 서버 불필요
  - 실제(2026-10-17 전국 수집): 3,426건 · 중복 0 · 865.6KB (gzip 97.8KB)
- 저장: `data/bonded-area-code.json` — 머리에 `{"source", "updatedAt", "count", "scope"}`
- 갱신: 분기 1회 수동 (`scripts/fetch-bonded-areas` 재실행). 다음 갱신 예정일을 데이터 안내 패널에 표시
- 공개: 공공데이터이므로 공개 저장소 OK. 단 API 인증키·원본 엑셀의 개인정보 컬럼(담당자 전화 등)은 제외

### 3-2. 필드 (정제 후)
| 필드 | 설명 |
|---|---|
| `code` | 장치장(보세구역) 부호 — 숫자 8자리, 문자열로 저장(앞자리 0 보존). API005 `snarSgn` |
| `name` | 장치장명 (공식 명칭). API005 `snarNm` |
| `customs` | 관할세관부호 3자리 — 수집 때 요청에 넣은 `jrsdCstmCd`. 부호 앞 3자리와 다를 수 있으므로(030 응답 366건 중 48건) 부호에서 잘라 쓰지 않는다 |
| `customsName` | 관할 세관명 — `data/customs-codes.json`(API019 A09)에서 `customs`로 찾아 채움. 파일이 없거나 목록에 없는 부호면 빈칸 |
| `region` | 지역 그룹 — 부산 / 인천 / 광양 / 평택 / 울산 / 서울·경기 / 경남 / 공항 / 기타. **관할세관 기준, 지원센터는 소재지 기준**(추정 아님). 공항세관(040·041·140) → 공항, 부산·용당세관 → 부산, 인천세관 → 인천, 서울·파주·성남·안산·수원·안양세관 → 서울·경기, 양산·마산·창원·경남남부·경남서부세관 → 경남 등. 지원센터 예: 안산세관 부평지원센터 → 인천, 평택세관 대산지원센터 → 기타. 매핑표는 `scripts/region-map.mjs` |
| `type` | 구분(**추정**) — CY(터미널) / CFS / 보세창고 / 지정장치장 / 세관검사장 / 보세공장 / 보세판매장 / 자유무역지역 / 보세구역외장치 / 공항화물 / 기타. API005에 구분 항목이 없어 장치장명 키워드 → 하역장소 여부 → 부호 자리 패턴 순으로 분류(규칙은 3-3, 코드는 `scripts/classify-type.mjs`) |
| `typeBasis` | 구분 근거 — `airport`(공항세관 관할 항공사·화주터미널) / `name`(이름 키워드) / `unloading`(하역장소 Y) / `code`(부호 자리) / `none`(기타). 화면의 "추정" 표시 설명용 |
| `address` | 주소 (있으면). API005 `snarAddr` |
| `aliases` | 통칭·약칭 (예: 터미널 영문 약칭). 1차는 수동 보강 10~20건, 이후 제보로 확장. 원본은 `data/bonded-area-aliases.json`(03077011 → `HPNT`·`현대신항`, 03077013 → `PNIT`) |

### 3-3. 규칙
- 검색: 공백·괄호·㈜·주식회사 무시, 대소문자 무시, 초성 일치 지원, `aliases` 포함 검색, 코드는 부분 일치
- 정렬: 정확 일치 → 시작 일치 → 부분 일치 → 이름순
- 코드 표기: 항상 원본 자릿수 유지(앞자리 0 절대 손실 금지)
- 구분(type) 추정 규칙 (2026-10-17 확정, 목표: 전국 기준 기타 15% 이하 → 결과 8.2%). 구분 목록은 관세법상 보세구역 구분(지정장치장·세관검사장·보세창고·보세공장·보세판매장)에 실무 구분(CY·CFS·공항화물), 자유무역지역, 보세구역외장치를 더한 것
  - **0단계 공항세관 관할 화물터미널** — 관할세관이 인천공항세관(040)이고 이름에 `항공`·`터미널`·`터미날`이 있으면 공항화물(대한항공·아시아나항공·상용화주터미널 등). 단 1단계 이름 키워드로 CY 외의 구분(지정장치장·보세판매장·보세창고 등)이 잡히면 그 구분을 따른다
  - **1단계 이름 키워드** — 아래를 위에서부터 찾아 먼저 걸리는 것 적용
    1. 지정장치장: `지정장치장`
    2. 세관검사장: `세관검사장`, `검사장`
    3. 보세구역외장치: `보세구역외`
    4. CFS: `CFS`, `컨테이너화물조작장`
    5. 보세판매장: `면세점`, `보세판매장`, `인도장`, `여객터미널점`·`출국장점`·`입국장점`(공항 면세점 지점명) — 공항 안이어도 화물이 아님
    6. 공항화물: `공항`, `항공화물`, `항공`(**앞이 한글이 아닐 때만** — 포항공장·인천항공동물류·항공부품 제조사 상호 제외), `화물터미널`
    7. 보세창고(탱크터미널): `탱크터미널`, `탱크터미날` — CY보다 먼저 걸러냄
    8. CY(터미널): `컨테이너터미널`, `컨테이너 터미널`, `CY`, `터미널`, `터미날`
    9. 자유무역지역: `자유무역지역`
    10. 보세공장: `보세공장`, `공장`
    11. 보세창고: `보세창고`, `창고`, `물류센터`, `냉장`, `냉동`, `물류`, `로지스`, `로지텍`, `로직스`, `디스트리파크`, `센타`, `센터`, `종합보세`, `크로스독`
  - **2단계 하역장소 보조** — 이름으로 판단이 안 되고, 부호 4~5번째 자리가 `12`·`77`·`78`이며, API005 하역장소 여부(`ldunPlcSnarYn`)가 Y면 CY
  - **3단계 부호 자리 패턴** — 이름으로 판단이 안 될 때만. 부호 4~5번째 자리: `01` 세관검사장, `02` 지정장치장, `06`·`07`·`10`·`11`·`13`·`70` 보세창고, `12` CY, `86` CFS, `16`·`18`·`20` 보세공장, `19` 보세구역외장치, `21`·`22`·`24`·`25` 보세판매장, `77`·`78` 자유무역지역. 부산세관 366건에서 관찰하고 전국으로 점검한 패턴이며 공식 근거 없음
  - **4단계** 그 외: 기타
  - 영문 `CFS`·`CY`는 앞뒤가 영문자가 아닐 때만 인정(예: AGENCY의 CY 제외)
  - 2단계를 3단계보다 먼저 두는 이유: `77`·`78`을 자유무역지역으로 먼저 판정하면 신항 터미널(예: 03077011)이 CY가 되지 못함
  - 규칙 변경은 `scripts/classify-type.mjs`의 표(`TYPE_RULES`·`UNLOADING_SEGMENTS`·`CODE_SEGMENT_TYPES`)만 고친다
  - 구분은 항상 추정값이므로 화면에서 "추정" 표시를 붙인다(CLAUDE.md 금지 규칙)
- 금지: 추정 코드 표시, 세관명 추정 표시, 폐지·특허 만료 장치장을 현행처럼 표시(원본에 상태값이 있으면 "만료" 태그로 구분 — API005에는 상태값 없음)

- 행/카드 클릭 시 상세 펼침: 주소, 별칭, **내 메모 편집**, 복사 형식 3종

**복사 형식 3종** (설정 기억)
1. 한 줄: `장치장: {name} / 장치장코드: {code}` (기본, 관세사 전달용)
2. 표: 여러 건 선택 시 `장치장명\t코드` 줄바꿈 — 엑셀·메일 표에 붙음
3. 코드만: `{code}`

- 빈 상태: "장치장명이나 코드를 입력하세요. 초성 검색도 됩니다."
- 결과 없음: "일치하는 장치장이 없습니다. 이름 일부만 입력해 보세요." + 오류 제보 링크
- 복사 완료 토스트: "복사됨 — 관세사에게 붙여넣으세요"
- 액센트 버튼(코발트, 페이지에 1개): **"관세사 전달용 복사"** (선택 항목 기준)

**localStorage 키**: `mft:bonded-area-code:favorites`, `:recent`, `:memos`, `:view`, `:copyFormat`
