| 항목 | 내용 |
|---|---|
| 종류 | 사이트 공통 페이지(도구 아님 — tools.json 항목 없음, D번호 없음) |
| 파일 | `updates.html` · `site.json`의 `updates` 칸 · `shared/page.js`(상단 바·푸터 링크, 도구 페이지 링크) · `shared/layout.css`(상단 바 링크) |

## 1. 왜

도구마다 "만든 과정"은 있지만 배포 뒤에 바뀐 것과 사이트 전체 변경은 공개된 기록이 없었다. 또 만드는 사람이 이용자에게 "지금 뭘 만들고, 뭘 고민하는지"를 짧게 전할 곳이 없었다. 한 페이지에 모아 날짜순으로 보여 준다.

## 2. 내용 — 무엇을 어디서 읽나

| 줄 종류 | 화면 표시 | 원본 | 규칙 |
|---|---|---|---|
| 새 도구 | 검정 태그 "새 도구" + "{도구 이름}을/를 열었어요" + 도구 한 줄 소개 | `tools.json` history의 **마지막 `배포` 줄** 날짜 | live 도구만. 배포 준비·재배포 줄은 따로 보여 주지 않음 |
| 기능 | 회색 태그 "기능" + 그 줄 내용 | `tools.json` history의 **첫 `배포` 줄 뒤** `수정` 줄 | 기획·구현 줄과 배포 전 데이터 줄은 도구 페이지 "만든 과정"에만 |
| 데이터 | 회색 태그 "데이터" | 첫 `배포` 줄 뒤 `데이터` 줄(예: 고시 갱신 — 감시 자동화가 덧붙임) | 〃 |
| 사이트 | 회색 태그 "사이트" | `site.json` `updates.changes` | 도구 하나에 속하지 않는 변경(랜딩·공통 기능) |
| 메모 | "만드는 사람 메모" + 종류(고민 중 / 바꾼 이유 / 만드는 중) + "의견 보내기" | `site.json` `updates.notes` | 날짜 약속 안 함, 두 줄 안, 끝나면 `result`("했어요 …"/"접었어요 …")를 채워 닫음 |
| 요즘 만드는 것 | 맨 위 검정 블록: D번호(영역 색 큰 숫자)·도구 이름·단계 pill·메모 한 단락·의견 보내기 | `site.json` `updates.now` | 만드는 도구가 없으면 블록을 그리지 않음 |

- 적는 기준: 이용자가 느끼는 변화만(새 도구·기능·데이터 갱신·계산 규칙·주요 문구). 내부 정리는 안 적음. 지난 줄은 고치지 않고 덧붙이기만
- "의견 보내기"는 `site.json` 연락의 첫 채널(지금 이메일 — 제목 "[업데이트 의견] …"을 채워 엶). 댓글·투표는 서버가 필요해 안 함

## 3. 화면

1. 머리: "업데이트"(display-l) + 한 줄 소개
2. 요즘 만드는 것(검정 블록, `updates.now`가 있을 때만)
3. 거르기: 종류 pill(전체 · 새 도구 · 기능 · 데이터 · 메모 · 사이트) + 도구 고르기(전체 · 도구별 · 사이트). 주소 `?tool={slug}`로 들어오면 그 도구만 골라 둔 상태
4. 목록: 날짜 | 종류 태그 | 내용(+ 도구 칩 → 도구 페이지). 같은 날 줄은 날짜를 한 번만. 20줄씩, "이전 기록 더 보기"
5. 끝: "도구마다 만든 과정 전체는 각 도구 페이지에 있어요"

들어오는 길: ① 모든 페이지 상단 바 "업데이트" 글자 링크(page.js가 붙임, 지금 페이지면 진하게) ② 도구 페이지 "만든 과정" 끝 "업데이트 소식에서 이 도구만 보기" ③ 모든 페이지 푸터 "업데이트". 랜딩 "최근 소식" 한 줄은 메모가 쌓인 뒤(보류)

디자인: 색은 영역 태그와 검정 블록의 큰 D번호에만. 실행 버튼(액센트) 없음. 모션은 스크롤 리빌만.
